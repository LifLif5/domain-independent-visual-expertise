# Setting up the Code Ocean environment for EyeTrackingAnalysis

This folder is laid out like a Code Ocean **Compute Capsule**:

```
code/        -> /code     (notebooks + analysis modules)
data/        -> /data     (input data)
results/     -> /results  (written by a reproducible run)
environment/               (Dockerfile + dependency files)
run                        (reproducible-run entry point)
```

The original capsule used the **base environment** (nothing installed), which is
why no notebook ran. Everything needed to rebuild a working environment is now
in `environment/`, and the notebooks were made working-directory independent so
that they run both inside Code Ocean and locally.

> `REPRODUCING.md` is generated by Code Ocean from the capsule settings. It
> still describes the *base environment*, because the capsule has not been
> rebuilt yet; it is regenerated automatically once the new environment exists.

---

## 1. What is in `environment/`

| File | Purpose |
|------|---------|
| `Dockerfile` | Complete image definition: Python 3.10 + scientific stack, Jupyter, R 4.4 with `lme4`/`lmerTest`/`broom(.mixed)`/`emmeans`/easystats, `rpy2`, and `pymer4`. |
| `environment.yml` | The conda part (channel `conda-forge`, `nodefaults`). Can be used directly by the Code Ocean Environment Editor or by `conda env create`. |
| `requirements.txt` | The pip part: `pymer4==0.9.2`, `great_tables`, `formulae`, `joblib`, `pyarrow`. |

### Why `pymer4==0.9.2` (and why R is needed)

`code/statistic_checks/GLMs.py` and `MixedEffectStatistics.py` use pymer4, a
thin Python wrapper around R's `lme4`. pymer4 0.9.x is the version the
notebooks were written against:

* models are lowercase classes: `from pymer4.models import lmer, glmer`;
* the model data must be a **polars** `DataFrame` (`pl.DataFrame(df)`);
* results are read from `model.result_fit`, `model.summary()._tbl_data`
  (great_tables) and `model.data["fitted"] / ["resid"]`.

pymer4 also needs R with `lme4`, `lmerTest`, `broom`, `broom.mixed`, `emmeans`,
`boot`, `tibble` and the easystats bundle (`insight`, `parameters`,
`performance`, `report`). All of it is installed by `environment.yml`, so no R
code has to be run by hand.

## 2. Route 1 (recommended) – publish on GitHub, then *Clone from Git*

This folder is already a git repository with a single commit
(`Initial commit`), and `/data/` is excluded by `.gitignore`, so the first push
contains only code + environment (~1.2 MB).

**a. Publish the repo** (no `gh` CLI is installed on this machine, so create the
repository in the browser):

* github.com → *New repository* → name `EyeTrackingAnalysis` → **Private** →
  *create without* README/.gitignore/licence.
* then, in this folder:

```bash
git remote add origin https://github.com/<your-user>/EyeTrackingAnalysis.git
git push -u origin main
```

If the author e-mail of the commit should be yours before pushing:

```bash
git config user.name  "Your Name"
git config user.email "you@example.com"
git commit --amend --reset-author --no-edit
```

**b. Connect GitHub to Code Ocean** (once per account/organisation):
*Settings → Git Providers → GitHub → Connect* and authorise via OAuth. Skip this
if your deployment shows *Clone from &lt;GitHub organisation&gt;* on the *New
Capsule* screen, which means it is already connected.

**c. Create the capsule**: *New Capsule → **Clone from Git*** → paste the HTTPS
URL `https://github.com/<your-user>/EyeTrackingAnalysis.git`.

What Code Ocean does with the repository:

| Repo path | Capsule location |
|-----------|------------------|
| `code/` | `/code` (Code panel) |
| `environment/Dockerfile`, `environment.yml`, `requirements.txt` | `/environment` – **this is what the environment build uses** |
| `run` (root) | capsule root – the file a *Reproducible Run* executes |
| `README.md`, `CAPSULE_SETUP.md`, `REPRODUCING.md` | capsule root ("Other Files") |
| `.codeocean/*.json` | created by Code Ocean on the first commit and versioned for you (starter environment, resources, attached data) |
| `data/` | **absent** – see (e) |

Unlike *Copy from Git*, this keeps a **two-way link**: every change committed in
the capsule timeline can be pushed with *Sync with GitHub*, and *Check for
updates → Sync with GitHub* pulls commits made here.

**d. Starter Environment first**: open the Environment tab and select a
mamba/conda starter (e.g. *Mambaforge 3 / Python 3.10 / Ubuntu 22.04*) before the
first build; `environment.yml` pins Python 3.10 itself, so the starter's Python
version does not matter.

The build then runs `environment/Dockerfile` from the repo. Its first line is
`FROM condaforge/miniforge3:24.11.3-0` (Docker Hub). If your deployment cannot
pull from Docker Hub, unlock the Dockerfile, replace **only** the `FROM` line with
the base image of the starter environment you selected, and keep the rest of the
file unchanged (it is self-contained: conda-forge env update → pip install →
smoke test). The build takes 10–20 min the first time.

**e. Add the data**: git never carries it (and GitHub rejects the 100 MB
pickle). Upload the five files into the capsule's **Data** panel → `/data`:
`simple_df_search.csv`, `search_performance_long.csv`, `mot_long_dataframe.csv`,
`simple_df_mot.csv`, `movement_phase_full.pkl` (≈120 MB).

**f. Run**: *Reproducible Run* now works, because `run` sits at the capsule root.
See §5.

## 3. Route 2 – start from an empty capsule and paste the Dockerfile

Use this if you cannot connect GitHub.

1. **Create a new capsule** (*Capsules → New Capsule*).
2. **Choose a Starter Environment** that is mamba/conda based, e.g.
   *Mambaforge 3 / Python 3.10 / Ubuntu 22.04*. The starter Python version does
   not matter – `environment.yml` pins Python 3.10 itself.
3. **Upload the files**: drag the contents of this folder into the capsule so
   that `/code` contains `code/`, `run`, `environment/` (and this file), and
   `/data` contains the five data files (`mot_long_dataframe.csv`,
   `simple_df_mot.csv`, `simple_df_search.csv`, `search_performance_long.csv`,
   `movement_phase_full.pkl`; ≈120 MB in total). Skip `__pycache__/` and
   `results/` – they are generated.
   *The repository's `.gitignore` excludes `/data/`, so when you clone/upload
   through git, add the data afterwards in the capsule's **Data** panel.*
4. **Install the environment** – either way works:

   **(a) Unlock and paste the Dockerfile (fastest, fully pinned)**

   * Open `/environment/Dockerfile` in the Environment Editor.
   * Unlock it (padlock icon). This permanently disables the Environment
     Editor, which is fine because everything lives in the file now.
   * Keep the **`FROM` line** that Code Ocean generated (it points at the
     `codeocean/mambaforge3` image of your deployment) and delete the rest of
     the file.
   * Paste everything from `environment/Dockerfile` *below* its `FROM` line –
     i.e. the `ENV`, `COPY environment.yml requirements.txt /tmp/env/`,
     the `RUN mamba env update …`, the `pip install …` and the smoke-test
     `RUN python -c "…"`.
   * `environment.yml` and `requirements.txt` must sit in the capsule's
     `/environment` folder, which is the build context (`COPY` paths are
     relative to it).
   * Save → the environment is rebuilt (10–20 min the first time; the R
     packages are large).

   **(b) Use the package managers of the Environment Editor**

   * Add `conda-forge` as a channel (gear icon → *Channels*).
   * Add every dependency of `environment/environment.yml` through the *Conda*
     package manager and every line of `environment/requirements.txt` through
     the *pip* package manager.
   * Keep the pins (`python=3.10`, `pandas=2.2`, `r-base=4.4`,
     `pymer4==0.9.2`); an unpinned `pymer4` resolves to 0.8.x, whose API does
     not match the notebooks.

5. **Open the IDE / restart the Cloud Workstation** and check:

   ```bash
   python -c "import pymer4, rpy2, polars, pandas; print('ok')"
   Rscript -e 'library(lme4); library(lmerTest); library(broom.mixed); cat("ok\n")'
   ```

## 4. Route 3 – reproduce the environment locally (Docker or conda)

With Docker (builds the same image Code Ocean builds):

```bash
cd EyeTrackingAnalysis
docker build -t eyetracking-env environment/
docker run --rm --platform linux/amd64 \
  -v "$PWD/code":/code -v "$PWD/data":/data -v "$PWD/results":/results \
  -w /code eyetracking-env bash run
```

Without Docker, with conda/mamba (this is how the environment was validated
locally):

```bash
conda env create -f environment/environment.yml      # creates the env "eyetracking"
conda activate eyetracking
pip install -r environment/requirements.txt          # pymer4 + pure-python deps
```

If you get a `CondaToSNonInteractiveError` (Terms of Service for
`repo.anaconda.com`), your `~/.condarc` still lists the `defaults` channel –
force conda-forge only:

```bash
conda create -n eyetracking --override-channels -c conda-forge \
      python=3.10 "numpy>=1.26,<3" pandas=2.2 "scipy>=1.11" "statsmodels>=0.14" \
      "scikit-learn>=1.3" "matplotlib>=3.7" "seaborn>=0.13" "shapely>=2.0" \
      "pyyaml>=6" "polars>=1.29,<2" "jupyterlab>=3" "notebook>=6" \
      "nbconvert>=7" "nbclient>=0.7" "nbformat>=5" "ipykernel>=6" matplotlib-inline \
      r-base=4.4 "rpy2>=3.5.11,<4" r-lme4 r-lmertest r-broom r-broom.mixed \
      r-emmeans r-boot r-tibble r-optimx r-insight r-parameters r-performance r-report
conda activate eyetracking && pip install -r environment/requirements.txt
```

## 5. Running the analysis

**Interactively** – open the notebooks in this order (the third one reads the
table produced by the first one):

1. `code/search_analysis/search_features.ipynb` → `combined_zscore_search.csv`
2. `code/search_analysis/performance_analysis_search.ipynb`
3. `code/mot_analysis/article_mot_analysis.ipynb`

**Reproducible Run** – the capsule entry point is the `run` file:

```bash
bash run          # inside Code Ocean, or locally in the repo root
```

`run` executes the three notebooks with `jupyter nbconvert --execute` and writes
the executed copies (figures and tables inline) to `/results` (or `./results`
outside Code Ocean):

```
results/search_features_executed.ipynb
results/performance_analysis_search_executed.ipynb
results/article_mot_analysis_executed.ipynb
results/combined_zscore_search.csv
```

A full run takes roughly 5–15 minutes; the mixed-effects models in
`search_features.ipynb` and `article_mot_analysis.ipynb` dominate. `run` returns
a non-zero exit code if any notebook fails.

Notes:

* Figures are kept in the executed notebooks (the matplotlib *inline* backend is
  used; forcing `MPLBACKEND=Agg` would drop them).
* `combined_zscore_search.csv` is written to `/results` by the notebook itself
  (on a local run it is written next to the notebook instead); `run` also copies
  it next to the notebook when that folder is writable, which is a harmless
  no-op in Code Ocean (`/code` is read-only during a run).
* `RESULTS_DIR=<dir> bash run` overrides the output folder (handy for local
  testing without touching `./results`).

### Git workflow (only for the GitHub-linked capsule of Route 1)

* Local → capsule: `git push`, then in the capsule *Check for updates → Sync with
  GitHub*.
* Capsule → local: commit in the capsule timeline, then *Sync with GitHub*;
  `git pull` here.
* Code Ocean maintains its own root `.gitignore` (it already ignores `/data`,
  `/results`, `/scratch`) and may replace the one in this repository on the first
  commit – harmless, the local copy is only there to keep data out of git.
* `.codeocean/*.json` (starter environment, resources, attached data assets) are
  written by Code Ocean and committed like normal files – do not edit them by
  hand.

## 6. Code changes that were required

The notebooks were written on Windows (absolute `C:\Users\...` paths, `..\`
separators) and relied on `utils.py` sitting next to them. The following
minimal changes make them run unchanged in a capsule (and on macOS/Linux).
Analysis logic, parameters and plotting style were **not** touched.

| File | Change |
|------|--------|
| all three notebooks, first cell | The `project_root = Path().resolve().parent` block was replaced by a `_find_code_dir()` helper that walks up from the working directory until it finds `utils.py` (or `code/utils.py`). It defines `CODE_DIR` and `DATA_DIR` (`/code` and `/data` inside Code Ocean) and appends `CODE_DIR` to `sys.path`. |
| `search_analysis/search_features.ipynb` | `../data/simple_df_search.csv`, `../data/search_performance_long.csv` → `DATA_DIR / ...`; final cell writes `combined_zscore_search.csv` to `/results` when that folder exists (otherwise next to the notebook). |
| `search_analysis/performance_analysis_search.ipynb` | `../data/search_performance_long.csv` → `DATA_DIR / ...`. |
| `mot_analysis/article_mot_analysis.ipynb` | `../data/mot_long_dataframe.csv`, `../data/simple_df_mot.csv`, `../data/movement_phase_full.pkl` → `DATA_DIR / ...`; the absolute `C:\Users\...\combined_zscore_search.csv` → the first existing file of `CODE_DIR/search_analysis/…`, `/results/…`, `cwd/…` (the table is written to `/results` inside Code Ocean, where `/code` is read-only). |
| `mot_analysis/mot_helpers.py` | `CONFIG_PATH` was an absolute Windows path, so `mot_config.yaml` was never loaded and `target_ball_positions_at_times()` could not work. It now resolves to `Path(__file__).resolve().with_name("mot_config.yaml")`. |

Nothing else in `code/` was modified.

## 7. Troubleshooting

* **`ImportError: cannot import name 'lmer'` / `'Lmer'`** – wrong pymer4
  version. 0.8.x exposes `Lmer`/`LmerTest`, 0.9.x exposes `lmer`/`glmer`.
  Install `pymer4==0.9.2`.
* **`Conversion 'py2rpy' not defined for objects of type DataFrame`** – a pandas
  frame was passed to pymer4; wrap it in `pl.DataFrame(df)` (already done in
  `GLMs.py`).
* **`RRuntimeError: could not find function "lmer"` or `there is no package
  called 'lmerTest'`** – only the pip part was installed. Install
  `environment.yml` too (it provides R and the R packages).
* **`rpy2` build failures** – never `pip install rpy2`; take `r-base` +
  `rpy2` from conda-forge so both are built against the same R.
* **`CondaToSNonInteractiveError`** – the Anaconda `defaults` channel is being
  pulled in from `~/.condarc`. Use `--override-channels -c conda-forge` (see
  section 3); `environment.yml` already lists `nodefaults`.
* **Environment rebuild is slow / times out** – the R + easystats dependency
  tree is large; build once and reuse the capsule environment.
* **Plots are missing from the executed notebooks** – the run must use a backend
  that supports inline output. `run` sets
  `MPLBACKEND="module://matplotlib_inline.backend_inline"`; don't override it
  with `Agg`.
* **`FileNotFoundError: could not find code/utils.py`** – the notebook was
  started in a directory that is not inside the capsule (e.g. a random folder
  deeper than `/code`). Start it from `/code` or any of its sub-folders, or set
  the kernel working directory accordingly.
